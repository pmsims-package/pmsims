# pmsims 1.0.0

`pmsims` 1.0.0 is a substantial expansion of the simulation framework for
estimating the minimum sample size required to develop prediction models with
continuous, binary, and time-to-event outcomes.

## Highlights

- Four data-generating complexity levels are now available: linear, quadratic,
  quadratic with interactions, and the Friedman benchmark function.
- Predictor generation is much more flexible. Users can control nonlinear
  signal strength, correlation, predictor distribution, and binary predictor
  prevalence. The package now tunes the outcome-generating mechanism using the
  same data-generating configuration as the sample-size simulation itself, so
  the large-sample performance you ask for is the performance actually
  recovered.
- Built-in workflows support regression-based (linear, logistic, and Cox) and
  machine learning models (lasso, ridge, random forest, and XGBoost) for
  continuous, binary, and survival outcomes. Random-forest defaults and XGBoost
  tuning have also been refined.
- A new calibration-slope squared-error metric (`"csse"`) provides a criterion
  that penalises calibration slopes below and above the ideal value of one. It
  exists because the sample-size search needs a metric that improves
  monotonically with `n`: the calibration slope does so for classical
  regression models, which overfit and approach one from below, but not for
  penalised and tree-based learners, whose slope can approach one from either
  side and so meet a one-sided target at more than one sample size. Asking for
  `metric = "calibration_slope"` with lasso, ridge, random forest, or XGBoost
  now searches on the CSSE scale internally and translates the answer back, so
  targets and results remain on the calibration slope scale; `"csse"` can also
  be requested directly, with the target supplied on that scale.
- Sample-size searching is more robust, with improved adaptive bounds,
  better detection of apparently unreachable targets, safer handling of failed
  model fits or metric calculations, and clearer result summaries.
- Long runs are flagged before they start. The adaptive first stage is timed
  and extrapolated to the full search: runs expected to take more than 30
  minutes report the estimate, and runs expected to take more than two hours
  also warn and ask for confirmation before continuing. The prompt appears only
  in interactive sessions, so scripts and CI are unaffected, and it can be
  switched off with `options(pmsims.confirm_long_runs = FALSE)`.

## Interface changes

The wrapper interface has changed since 0.5.0. Predictor configuration is now
expressed through `complexity` and `data_control`, which groups options such as
nonlinear strength, correlation, predictor distribution, and binary predictor
prevalence. The top-level `predictor_type` and `binary_predictor_prevalence`
arguments have been removed in favour of `data_control` fields. See the updated
examples and function reference for the current interface.

Note that candidate predictors are now correlated by default
(`data_control$correlation = 0.3`), whereas 0.5.0 generated independent
predictors, so sample sizes are not directly comparable across versions unless
`correlation = 0` is set explicitly.

## Install

```r
# install.packages("remotes")
remotes::install_github("pmsims-package/pmsims", ref = "v1.0.0")
```

`1.0.0` is available from GitHub and is not yet a CRAN release.
